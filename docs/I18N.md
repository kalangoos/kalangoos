# Idiomas no KalangoOS

O KalangoOS mira **qualquer idioma que o Linux consiga instalar** — não só português. Isso cobre três camadas
diferentes; confundir as três é o que costuma parecer “falta de idioma”.

| Camada | O quê | Onde |
|---|---|---|
| **Interface Kalango** | Rótulos do shell, aprovação, instalador, entrada, ferramentas do `kalangod` | `crates/kalango-i18n` (`tr` / `trf`, catálogos JSON) |
| **Sistema (glibc / Ubuntu)** | `LANG`, formatos, mensagens de pacotes de terceiros | `localectl`, `language-pack-*`, Configurações › Data e idioma |
| **Entrada de texto** | Teclado, IME (CJK, índicos…), fontes com glifos | `xkeyboard-config`, IBus, Noto |

## Como a interface escolhe o idioma

1. Cordas no código são **em inglês** e servem de id: `tr("Date and language")`.
2. Catálogos embutidos: `crates/kalango-i18n/locales/<locale>.json` (hoje: `pt_BR`).
3. Ordem de resolução:
   - `KALANGO_UI_LANG` (teste / agente; precisa existir **antes** do primeiro `tr` no processo)
   - `LANGUAGE` (lista `pt_BR:en_US`)
   - `LC_ALL` → `LC_MESSAGES` → `LANG`
4. Sem catálogo ou sem chave → **inglês** (o próprio msgid).
5. Troca em Configurações › Data e idioma chama `idioma.sistema` no `kalangod` e vale **no próximo login**
   (o catálogo ativo fica fixo na vida do processo).

APIs úteis: `available_catalogs()`, `has_ui_catalog()`, `active_locale()`, `normalize()`, `system_locale()`.

Instruções para tradutores: `crates/kalango-i18n/locales/README.md`.

## “Todos os idiomas do Linux”

- **Selecionar** um locale já instalado: a tela *Data e idioma* lista o que `locale -a` oferece e grava via
  `localectl` (`idioma.sistema`). Isso já existe no desenho 51040.
- **Traduzir a UI Kalango** para um idioma novo: novo JSON + entrada em `CATALOGS` (ou Weblate → PR). Até lá a
  pessoa vê a UI em inglês e o restante do sistema no idioma escolhido, se o `language-pack` estiver instalado.
- **Pacotes de idioma Ubuntu** não vão todos no ISO (o tamanho explode). A imagem traz o necessário para pt e a
  base tipográfica/IME; outros `language-pack-*` entram sob demanda (apt / futuro fluxo na própria tela).
- **RTL** (árabe, hebraico): o GTK 4 respeita a direção do locale; ainda não há revisão visual dedicada no Design
  System — tratar como trabalho de tela quando o primeiro catálogo RTL entrar.
- **IME / CJK**: IBus + fontes Noto na imagem (ver `imagem/pacotes.txt`). Layouts de teclado vêm do instalador e
  das configurações existentes.

## Weblate

Arquivo de componente: `weblate.yml` na raiz. Hospedagem ainda não está ligada; quando estiver:

- Componente apontando para `crates/kalango-i18n/locales/*.json`
- Idioma fonte: inglês (msgid)
- PRs automáticos para o repositório `kalangoos/kalangoos`

Até lá: contribuições por pull request com o JSON completo ou parcial.

## Imagem e fontes

Na `imagem/pacotes.txt`:

- `language-pack-*-pt-base` — mensagens do sistema em português
- `language-pack-*-en-base` — mensagens do sistema em inglês
- `fonts-noto-core`, `fonts-noto-color-emoji` — cobertura Unicode ampla sem o ISO CJK completo
- `ibus`, `ibus-gtk4` — método de entrada para idiomas que não cabem num teclado simples

CJK completo (`fonts-noto-cjk`) fica documentado como pacote recomendado pós-instalação (centenas de MB).

## O que não entra neste documento

- **Idioma das respostas do agente** (`idioma_respostas` nas Configurações): preferência do modelo, não do
  catálogo `tr`.
- **Novo seletor visual** além do que o Design System já tem em *Data e idioma*: qualquer mudança de layout
  passa pelo FigCraft antes do código (`AGENTS.md`).

## Checklist para um idioma novo na UI

1. Catálogo JSON + `CATALOGS`.
2. `cargo test -p kalango-i18n --locked`.
3. Login com `LANG=<locale>.UTF-8` (ou `KALANGO_UI_LANG`) e captura das telas críticas.
4. Se for RTL ou CJK: conferir fontes/IME e abrir issue de revisão no Design System.
